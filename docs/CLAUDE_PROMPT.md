## 2. Что за проект

**AI Team System** — локальная (браузер-first) мультиагентная платформа: пользователь
общается в браузере с «командой» из 7 ИИ-специалистов (TeamLead, Architect, Backend,
Frontend, DevOps, Tester, Documentalist), и они вместе делают проект: от описания идеи
до файлов на диске.

Технологии: Python 3.10+ (проверено на 3.13), FastAPI + uvicorn, Jinja2-шаблоны, ванильный
JS без сборки, SQLite, локальные модели через Ollama, мульти-провайдерный роутер моделей.

Пользователь: **новичок**, который пришёл в ИИ и не понимает сленга, но хочет научиться
и что-то сделать своими руками.

## 5. Жёсткие ограничения

1. **Всё бесплатно.** Никаких обязательных платных подписок. Локальные модели — основной
   путь, бесплатные тарифы внешних API — ускорение. Платное может быть только опцией.
2. **Работает из РФ без VPN.** Провайдер, недоступный из России, не может быть обязательным.
   (OpenRouter с 27.06.2026 не обслуживает РФ — учитывать как данность.)
3. **Windows 10/11 — первая платформа** (проверено: Python 3.13, Ollama, `scripts/launcher.ps1`),
   но код кроссплатформенный: логика не должна зависеть от Windows.
4. **Секреты — только в `.env`.** В репозиторий ключи не попадают никогда, включая примеры
   с «похожими на настоящие» значениями.
5. **Тесты не ослаблять.** Команда: `python -m pytest tests -q --ignore=tests/test_integration.py`
   (сейчас 1516 проходят). Один тест падает на Windows по платформенной причине
   (`test_install.py::TestInstallScript::test_install_sh_executable` — exec-бит в NTFS);
   его нельзя «чинить» удалением или ослаблением проверки.
6. **Живой поток не ломается.** Чат и создание проекта должны работать после каждого шага.
7. **Git-дисциплина.** Коммиты — от владельца с пометкой агента, через
   `pwsh scripts/agent_commit.ps1 -Message "..." -Body "..." -Push`. Один шаг — один коммит.
8. **Маленькими шагами.** Никаких «перепишем всё». Каждый шаг проверяем и обратим.

## 6. Целевая архитектура (предложение)

### 6.1 Агент истины (главный дифференциатор проекта)

**Задача:** убрать фантазии ИИ. Любое утверждение о проекте должно подтверждаться фактом
из репозитория или явно помечаться как «нет данных».

**Три источника фактов:**
1. Индекс кода: символы (классы, функции, эндпоинты), конфиги, структура каталогов,
   README/доки — с точными позициями.
2. Project Brain — но только после того, как он начнёт реально наполняться
   (цели, решения, ограничения, риски).
3. Документация проекта, включая `docs/PROJECT_MAP.md`.

**Правила поведения:**
- Каждый ответ — с источником: `путь:строка`.
- Нет источника → «В коде этого нет» + что проверить.
- Никаких «примерно так», «обычно в таких проектах».

**Механика внедрения (двумя половинами):**
- *До генерации:* TeamLead запрашивает «пакет фактов» — существующие имена, сигнатуры,
  куда писать файл, какой стиль принят. Пакет вставляется в промпт агента.
- *После генерации:* верификатор проходит по ответу, вытаскивает упомянутые идентификаторы
  (импорты, вызовы, имена файлов) и проверяет их по индексу. Несуществующие — помечаются
  в UI как «не подтверждено». Это и есть практический анти-галлюцинационный контроль.

**Куда:** `core/truth/` (`index.py`, `facts.py`, `verifier.py`), роуты `/api/truth/facts`,
`/api/truth/verify`, панель «Источник правды» в UI.

**Приёмка:** на наборе из 20 вопросов о репозитории — 100% ответов либо со ссылкой,
либо с честным «нет данных»; верификатор ловит подсунутые несуществующие имена
(отдельный тест с фейковыми идентификаторами).

**Ограничение, о котором надо помнить (замечание ревью):** «ссылка существует» ≠ «ссылка
подтверждает ответ». Верификатор не поймает неверное утверждение вида «этот модуль делает X»,
если файл и строка реально есть. Поэтому в приёмку входит **смысловая проверка**: те же 20 вопросов
проходят ручную оценку по критерию «цитата действительно подтверждает ответ», результат — в отчёт.
Автоматика здесь только первый фильтр, а не замена проверке.

### 6.2 Оркестратор и автопоиск бесплатных моделей

**Уровни источников (в порядке приоритета):**

| Уровень | Что | Стоимость | Доступность из РФ | Как получить |
|---|---|---|---|---|
| T0 | Локальные модели Ollama (`qwen3:4b/8b/14b`) | 0 ₽ | ✅ проверено на этой машине | `ollama pull` или `scripts/pull_model_via_http.ps1` |
| T1 | Бесплатные тарифы внешних API (Groq, Google AI Studio, Cerebras, Mistral, GitHub Models) | 0 ₽ в пределах лимитов | ⚠️ **не проверено** — только пробником | регистрация у провайдера, ключ в `.env` |
| T2 | Локальный шлюз-агрегатор бесплатных тарифов (OmniRoute) | 0 ₽ | ✅ локальный адрес; состав провайдеров внутри — под вопросом | `npm install -g omniroute`; провайдер `omniroute` в коде есть (`core/model_router.py:190`) |
| T3 | РФ-агрегаторы (ProxyAPI, VseGPT) | платно | ✅ | опционально, для скорости |

**Правило:** ни один внешний источник не считается «рабочим по умолчанию». В каталоге у каждого —
поле `reachable_from_ru: yes | no | unknown` **с датой проверки**, а фактический статус выдаёт
только рантайм-пробник (`config/providers_state.json`). Список бесплатных тарифов устаревает быстро —
OpenRouter это показал.

**Что уже измерено (14.10.2026, с этой машины):**

| Хост | Результат |
|---|---|
| github.com | ✅ клон, pull, push работают |
| pypi.org, huggingface.co, hf-mirror.com, modelscope.cn | ✅ отвечают 200 |
| registry.ollama.ai | ⚠️ отвечает 200, но загрузка слоёв обрывается — работает обход `scripts/pull_model_via_http.ps1` |
| openrouter.ai | ❌ не обслуживает российские аккаунты и IP с 27.06.2026 |
| Groq, Google AI Studio, Cerebras | ⚠️ unknown — ключей нет, проверять нечем |

Эти данные — не гарантия, а точка отсчёта: статус всегда уточняется пробником в рантайме.

**Автопоиск («как и где брать»):**
1. Сканировать `.env` на наличие ключей — что уже есть.
2. Проверить доступность каждого источника лёгким пробником (ping/список моделей, таймаут 5 с).
3. Записать состояние в `config/providers_state.json`: доступен, задержка, лимиты, последняя ошибка.
4. Показать в UI каталог: «источник → что даёт → где взять ключ → статус».

**Скоринг «кто лучше пишет код»:**
- Локальный бенчмарк из 5–7 коротких задач (написать функцию, найти ошибку, объяснить код,
  отформатировать данные, ответить на вопрос по файлу).
- Метрики: доля успешных, время ответа, стоимость (0 для бесплатных).
- Результат — `config/model_scores.json`; роутер выбирает лучшую *доступную* модель
  под тип задачи, при равенстве — бесплатную.

**Что уже есть и надо достроить, а не переписать:** `ProviderHealth` (здоровье и cooldown),
`fallback_manager`, `model_registry` (парсинг каталога), `hardware_detector` (выбор модели
по VRAM). Доработки: включить `groq`/`deepseek`/`xai` в цепочку приоритетов (сейчас их там нет),
добавить универсальный провайдер `openai_compat` (любой OpenAI-совместимый адрес из `.env`).

**Приёмка:** без интернета система работает на локальной модели; при появлении бесплатного
ключа он поднимается в приоритет автоматически; в UI видно, кто сейчас отвечает и почему.

### 6.3 Учебный слой: сленг и лестница объяснений

**Глоссарий как данные:** `config/glossary.ru.json` — термин, синонимы, объяснение «на пальцах»
(с аналогией), точное объяснение, пример, связанные термины, «где встречается в проекте».
Начать с 150+ терминов: промпт, токен, контекст, температура, инференс, квантование, VRAM,
репозиторий, коммит, ветка, merge, pull request, форк, issue, CI/CD, линтер, тест, мок,

эмбеддинг, агент, оркестратор, патч, ревью, снапшот, откат.

**Инлайн-обучение:** при новичковом уровне термины в ответах агентов подсвечиваются
и раскрываются коротким пояснением; клик — карточка глоссария. Отдельная панель «Словарь»
с поиском и прогрессом («изучено / в процессе»).

**Лестница объяснений** (исправить фикцию и сделать реальной):

| Уровень | Как ведёт себя ИИ | Что видно в UI |
|---|---|---|

квиз по терминам, «объясни своими словами» с мягкой оценкой.

### 6.4 «Сцена» — визуализация команды

## 13. Работа двух ИИ над одним репозиторием

Проект могут вести несколько ассистентов (Claude, AutoClaw и другие). Чтобы они не переписывали
работу друг друга:

- **Один исполнитель.** В каждый момент код пишет только один ассистент; второй — планирует
  или проверяет. Договориться, кто есть кто, до начала шага.
- **Правило передачи.** Исполнитель перед работой делает `git pull` и называет коммит, с которого
  начал; после шага — коммит и пуш через `scripts/agent_commit.ps1`.
- **Один шаг — один коммит.** Тогда видно, кто что сделал, и шаг легко откатить.
- **Ревью отдельно.** Проверяющий не правит код молча: спорные места — в отчёт, решение — за автором.

Если исполнителем выступает ассистент без доступа к репозиторию и терминалу, он не может
ни сослаться на `путь:строка`, ни прогнать тесты — тогда он работает как архитектор и ревьюер,
а исполняет тот, у кого есть доступ (раздел 9: «работает без запуска» не считается).
