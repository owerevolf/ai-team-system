# WP6 — связка «план → исполнение»: план работ

**Цель:** живой поток перестаёт писать файлы напрямую и проходит через патчи с подтверждением.
Правило проекта: ИИ не должен молча менять файлы — сначала патч, потом «применить» от человека.

Сделаны шаги **1, 1b, 1c, 2, 3, 5** — цепочка «модель предложила → код проверил → патч → подтверждение → применение → откат» существует целиком:

**Шаг 4 сделан и проверен вживую 15.10.2026** — перевести обычную запись файлов (чат и «Создать проект») на патчи:
сейчас `agent_manager._create_file` пишет напрямую, после переключения пойдёт через движок патчей

живого потока, поэтому делается с запасом токенов и с проверкой, что чат и создание проекта не сломались.

## Шаги (один шаг — один коммит с тестом)

1. **Реальный генератор патча.** Новый модуль `patch_generator.py`: просит модель вернуть строгий
   JSON `{path: {"old": "...", "new": "..."}}`, проверяет, что фрагмент `old` действительно есть
   в файле, собирает `Patch` (типы из `patch_engine`), возвращает `None`, если модель недоступна.
   В `task_executor` вызов меняется на: сначала генератор, при `None` — прежний мок (совместимость).
2. **Починить approval в `task_executor.approve_patch()`** — выставлять `patch.approved = True`
   перед `apply_patch`; сейчас применение невозможно в принципе (проверка в `patch_engine.py:265`).
3. **Настоящий откат**: `workspace_runtime.restore_snapshot()` восстанавливает файлы из снапшота
   (сейчас только меняет состояние на `ROLLED_BACK`).
4. **Перевести `agent_manager._create_file` на патчи**: запись только через `PatchEngine`
   с подтверждением; прямая запись остаётся за флагом `AITEAM_AGENT_DRAFTS=1` для черновиков.
5. **Панель подтверждений в интерфейсе**: `welcome.js` + уже существующие роуты
   `/api/developer/approvals` и `/api/developer/approvals/action`; показывать diff и кнопки
   «применить» / «отклонить».
6. **Дымовой тест потока**: заглушка модели → план → патч → подтверждение → файл изменён,
   откат возвращает исходное состояние.
