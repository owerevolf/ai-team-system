# AGENTS.md — правила работы агентов в этом репозитории

## Коммиты

Автор и коммиттер любого коммита — **владелец репозитория** (значения
`user.name` / `user.email` из git config). Вклад агента фиксируется трейлером
`Co-authored-by` — GitHub показывает его как соавтора.

Агентские платформы подставляют в окружение `GIT_AUTHOR_NAME/EMAIL` и
`GIT_COMMITTER_NAME/EMAIL` (например `zwork <zwork@local>`). Эти переменные
перекрывают git config, поэтому коммит «уезжает» на служебное имя. Коммитить
нужно через обёртку, она возвращает авторство владельцу:

```powershell
pwsh scripts/agent_commit.ps1 -Message "fix: ..." -Body "детали правки"
pwsh scripts/agent_commit.ps1 -Message "..." -NoAdd -Amend   # переоформить последний коммит
pwsh scripts/agent_commit.ps1 -Message "..." -Push           # коммит и push
```

Перед первым коммитом в новом клоне проверь, что владелец задан:

```powershell
git config user.name; git config user.email
```

## Проверки перед коммитом

```powershell
python -m pytest tests -q --ignore=tests/test_integration.py
```

Один тест падает на Windows по платформенной причине:
`test_install.py::TestInstallScript::test_install_sh_executable` — у `install.sh`
нет exec-бита в файловой системе Windows. В CI на Linux он проходит, это
не регрессия. Не «чинить» его удалением или ослаблением проверки.

## Провайдеры моделей

- Локально: Ollama (`OLLAMA_BASE_URL`, `OLLAMA_MODEL`), режим `AI_MODE=local`.
- Любой OpenAI-совместимый эндпоинт: `OPENAI_COMPAT_BASE_URL`,
  `OPENAI_COMPAT_API_KEY`, `OPENAI_COMPAT_MODEL` (провайдер `openai_compat`).
- OpenRouter с 27.06.2026 не обслуживает российские аккаунты и IP — ключ
  имеет смысл только за пределами РФ.

## Гигиена репозитория

Не коммитить `venv*/`, `.cache/`, `*.log`, `.env` — они перечислены в
`.gitignore`. Ключи и токены живут только в `.env` (в репозиторий не попадают).

## Экономия токенов

Стоимость сессии определяется тем, сколько агент **читает и пишет**, а не размером проекта.
Правила для всех агентов:

1. **Не читать файл целиком, если нужен фрагмент.** Сначала поиск (`rg`), потом узкое окно чтения,
   и только затем — файл.
2. **Не перечитывать то, что только что написано.** Свежесозданный файл не нужен в контексте второй раз.
3. **Отчёт — до 10 строк.** Детали — в файл в `docs/`, а не в переписку.
4. **Не пересказывать сделанное дважды.** Ссылка на коммит или документ вместо повторного описания.
5. **Широкую разведку — субагентам.** Их ответ до 1000 знаков дешевле, чем чтение десятью файлами.
6. **Независимые вызовы — одним блоком.** Меньше круглых поездок, меньше служебного текста.
7. **Проверки по делу.** Один прогон тестов после изменения; повторные прогоны — только если что-то менялось.

Со стороны проекта: инференс локальной модели не тратит внешних токенов вообще, поэтому
`AI_MODE=local` — не только про независимость от блокировок, но и про экономию.

## Windows: запуск и модели

Одна команда поднимает всё: виртуальное окружение, зависимости, Ollama,
веб-сервер и браузер.

```powershell
pwsh scripts/launcher.ps1                 # обычный запуск, порт 8000
pwsh scripts/launcher.ps1 -Port 8010 -NoBrowser
```

Если `ollama pull` рвёт соединение с реестром (типовая ситуация в РФ —
`An existing connection was forcibly closed`), модель ставится напрямую
по HTTP пофрагментной докачкой:

```powershell
pwsh scripts/pull_model_via_http.ps1 -Model qwen3 -Tag 8b
```

Скрипт сам раскладывает манифест и слои в локальное хранилище Ollama,
после чего `ollama list` видит модель как обычно установленную. Повторный
запуск продолжает недокачанное.
